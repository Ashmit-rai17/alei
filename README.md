# Alei — why Indian insurers reject claims

India's insurance regulator publishes how *often* claims are rejected, but not *why*. The reasons
exist only inside decisions ("awards") of the Insurance Ombudsman, published as scanned-and-typed
PDF compilations that nobody can count. Alei turns 111 archived compilations into a structured,
privacy-redacted dataset of **7,650 awards**, labels the insurer's stated ground for rejection
against a frozen 12-category taxonomy with an LLM whose every label carries a verbatim, verified
quote, measures that against blind human labels, and ships a small classifier and a deterministic
extractor that run offline on IBM Z (LinuxONE).

> These are contested denials that reached an Ombudsman — a small fraction of all repudiations.
> The data describes grounds that were **challenged**, not grounds that are typical.

## Key results

| | |
|---|---|
| Corpus | 388 archived URLs → 111 PDFs → 10,337 pages → **7,650 awards** → 3,831 repudiation awards |
| **LLM labelling vs human** | **macro-F1 0.703** against 64 awards labelled independently and blind by a human |
| Classifier (TF-IDF + logistic regression) vs human | macro-F1 **0.541**, trained on 364 awards |
| Deterministic keyword baseline vs human | macro-F1 **0.546** (full text); 0.578 on the extracted ground sentence |
| Verbatim-quote verification | **93.8%** of LLM quotes found word-for-word in the award (97.4% ignoring punctuation/case) |
| Learning curve (classifier) | **0.32 → 0.44 → 0.50 → 0.54** at 90 → 180 → 270 → 364 training labels; still rising |
| Taxonomy completeness | the "other" category was used **0 times** across the 64 human-labelled awards |

Every figure, with its denominator and caveats, is in [docs/RESULTS.md](docs/RESULTS.md).
The LLM labelling layer and the dataset are the result; the classifier is a cheap on-device
approximation and is not presented as an accuracy claim.

## Repository layout

```
README.md                 this file
LICENSE                   MIT
requirements.txt          pinned environment for the full pipeline (development machine)
requirements-s390x.txt    pinned environment for the IBM Z / LinuxONE demo (see below)
src/                      all pipeline code, one folder per concern so each can be read alone
  run.py                    orchestrator for the acquisition → parsing → privacy stages
  acquisition/              finding and fetching source PDFs from the Internet Archive (network only here)
  parsing/                  PDF inventory, truncation detection, splitting books into one row per award
  privacy/                  redaction of personal data, and display-time masking for anything published
  labelling/                sampling, LLM labelling with quote verification, keyword rules, human-labelling hand-off
  modelling/                classifier training, prediction, human evaluation, learning curve
  reporting/                corpus statistics, outcome analysis, evidence explorer, final numbers, demo packaging
docs/                     methodology, the frozen taxonomy, results and limitations — read these to judge the work
  METHODOLOGY.md            how every stage works and why it was built that way
  TAXONOMY.md               the 12 repudiation grounds + G99, with the decision rules given to model and human alike
  RESULTS.md                every number we quote, generated by src/reporting/final_numbers.py
  LIMITATIONS.md            what the data and the models cannot tell you, selection bias first
data/                     empty in git: award text contains personal data (see data/README.md)
  samples/                  3 redacted, masked sample awards — the only award text in the repository
demo/                     the LinuxONE demo: rules vs classifier on 3 awards, one screen, no network
```

Each `src/` folder is separate because each has a different trust boundary: `acquisition` touches
the network, `parsing` and `privacy` touch raw personal data, `labelling` is the only stage that
calls an external API (redacted text only), and `modelling`/`reporting` read only redacted outputs.

## Pipeline

```
 1 discover     Wayback CDX API              -> data/manifest.csv            (388 URLs)
 2 download     live site, then archive      -> data/pdfs/                   (111 PDFs)
 3 inventory    pymupdf, truncation checks   -> data/inventory.parquet
 4 segment      book -> one row per award    -> data/awards.parquet          RAW, never leaves the machine
 5 redact       two-pass redaction           -> data/awards_safe.parquet     redacted
 6 sample       stratified labelling sample  -> data/label_sample.csv        (1,200; seed 20261018)
 7 label        Qwen via OpenAI-compatible API, quote verification, resumable
                                             -> data/labels.parquet          (443 awards labelled)
               + keyword rules               -> data/labels_rule.parquet     (1,499 ground sentences)
 8 train        TF-IDF + one-vs-rest LR, book-grouped split
                                             -> models/alei_clf.joblib
 9 evaluate     against blind human labels   -> data/human_eval.json, data/learning_curve.json
10 report       explorer, statistics, numbers -> data/explorer.html, data/corpus_stats.json, docs/RESULTS.md
```

## Reproducing it

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
python3.12 -m venv .venv-ship && .venv-ship/bin/pip install -r requirements-s390x.txt   # model training

# 1-2  acquisition (network; ~2 s between requests)
.venv/bin/python src/run.py --only discover download
# 3-5  inventory, segmentation, redaction, ground-phrase table
.venv/bin/python src/run.py                       # inventory segment redact phrases
# 6    labelling sample
.venv/bin/python src/labelling/sample_for_labeling.py
# 7    LLM labels (needs QWEN_API_KEY[_2,_3,…], QWEN_BASE_URL, QWEN_MODEL in .env), then rules
.venv/bin/python src/labelling/qwen_label.py --workers 2 --until 20:00
.venv/bin/python src/labelling/qwen_label.py --finalize
.venv/bin/python src/labelling/rule_labels.py
# 8-9  classifier (trained under the s390x pins), human evaluation, learning curve
.venv-ship/bin/python src/modelling/train.py
.venv-ship/bin/python src/modelling/human_eval.py data/prashant/phase2_label_completed.xlsx
.venv-ship/bin/python src/modelling/learning_curve.py
# 10   reporting
.venv/bin/python src/reporting/corpus_stats.py
.venv/bin/python src/reporting/outcome_analysis.py
.venv/bin/python src/reporting/build_explorer.py
.venv/bin/python src/reporting/final_numbers.py
.venv/bin/python src/reporting/build_demo.py --final --name alei_demo_v2
```

Data can live outside the repository: set `ALEI_DATA=/path/to/data`. Stages refuse to run on a
stale input. The labeller checkpoints every batch and resumes; with several API keys it moves to
the next when one hits its daily cap.

## The data

**Not committed:** raw award text (`awards.parquet`), redacted award text (`awards_safe.parquet`),
the source PDFs, LLM label files (they quote award text), the human-labelling sheets, the explorer
(it embeds award text) and model files. Ombudsman awards concern real people's insurance disputes
and medical histories. Redaction is measured, not perfect (see LIMITATIONS), so redacted text is
not published either.

**Committed:** the code, the taxonomy, the results, and 3 redacted sample awards in `data/samples/`.
The published output of the method is structured fields and citations — award id, insurer, date,
claim type, ground category, and the location of the supporting sentence — not award text.

Raw text never left the development machine. Only redacted text was sent to the labelling API.
The demo runs fully offline.

## IBM Z / LinuxONE

The demo runs on s390x. scikit-learn has no s390x wheel above 1.4; 1.9 falls back to a source build
that needs gfortran, which the target does not have. So the model is trained here under the target's
distro versions — `numpy 1.26.4, scipy 1.11.4, scikit-learn 1.4.1.post1, joblib 1.3.2`
(`requirements-s390x.txt`) — in a separate venv, and `.joblib` files are only ever produced there.

Validated:
- save under the pinned versions, load in a fresh isolated process, predict — identical output;
- the model file contains only scikit-learn objects; text preprocessing travels inside it as a
  regex, so `predict.py` needs nothing but scikit-learn;
- byte order: all 54 arrays forced to non-native (big-endian) order still predict correctly;
- on s390x itself, the same three awards give the same probabilities to two decimals as on arm64.

`demo/run_demo.sh` prints the machine, model load time, the keyword extractor (pure Python, no
dependencies) and the classifier on 3 held-out awards, with both measured scores, in ~1 s.

## Limitations

Selection bias comes first: these are disputes that reached an Ombudsman, so they over-represent
contested grounds and say nothing about how often each ground is used overall. The corpus is 63% one
insurer (LIC) and 83% death claims; all health awards come from one book; 2016–17 is missing; human
evaluation is one labeller on 64 awards. Full list: [docs/LIMITATIONS.md](docs/LIMITATIONS.md).
